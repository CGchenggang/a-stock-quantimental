# P13-M：行业相对强弱（AKShare/巨潮，无 Tushare Token 路线）

## 目标

在 P13-I～P13-L 连续未发现稳定增量后，测试“个股相对于其历史上当时所属行业的表现”是否包含超出通用市场/个股技术因子的增量信息。

本阶段严格区分：

- **行业归属生效时间**：由巨潮行业变更记录的“变更日期”构造；
- **数据可用时间**：项目为 PIT 安全设置的保守时间；
- **真实发布时间**：当前接口没有提供，不作假设。

## 数据源

AKShare 当前提供 `stock_industry_change_cninfo`，对应巨潮资讯 `p_stock2110`，返回股票行业归属变动记录，包括：

- 证券代码
- 变更日期
- 分类标准编码
- 行业编码
- 行业门类 / 行业次类 / 行业大类 / 行业中类

项目只使用**申银万国行业分类标准**。不再把某个固定的“分类标准编码”当作全局筛选条件，因为巨潮接口中的编码与具体分类体系/类别记录相关；程序按 `分类标准` 的人类可读名称筛选。

申万 2021 版将一级行业调整为 31 个，因此本阶段先固定一级行业，避免二、三级行业过细造成小样本和高方差。

## PIT 约定

从历史变更记录构造区间：

- `effective_from = 变更日期 00:00 +08:00`
- `effective_to = 下一次变更日期 00:00 +08:00`
- `available_time = 变更日期次日 16:00 +08:00`

最后一条记录的 `effective_to` 为空，表示截至导入数据末端仍有效。

这里的 `available_time` 是**项目保守安全约定**，不是巨潮实际发布时间。由于当前接口没有给出每条历史行业变更的发布时间，因此宁可延迟一天进入回测，也不把“变更日期”直接当成可获得时间。

一级行业代码采用项目内部规范：

`SW1:<一级行业名称>`

这样不把历史记录中的更细粒度“行业编码”误当成一级行业代码。

## 当前实现

- `src/astock_v2/industry.py`：行业归属 PIT 数据契约、可用性选择、重叠区间检查，以及规范化 CSV loader / coverage_start。
- `tests/test_industry.py`：PIT、区间、CSV loader、覆盖起点测试。
- `scripts/import_cninfo_industry_membership.py`：AKShare/巨潮历史行业变更 → PIT 一级行业区间。
- `tests/test_import_cninfo_industry_membership.py`：变更记录去重、冲突检测、区间构造测试。
- `scripts/check_industry_coverage.py`：检查每只股票的实际历史覆盖起点，并可按指定 event/decision time 做 PIT 可用性检查。
- `scripts/import_tushare_industry_membership.py`：仍保留作为备选数据源，但 P13-M 默认不再要求 Tushare Token。

## 第一阶段：单股可行性验证

先只验证 `300308`，不要一次跑 8 只。

在项目根目录：

```powershell
python scripts/import_cninfo_industry_membership.py `
  --symbol 300308 `
  --start 20200101 `
  --end 20260927 `
  --output data/industry/cninfo_sw1_membership.csv `
  --raw-output data/industry/cninfo_industry_change_raw.csv
```

成功后应看到：

```
300308: N SW industry-change rows
raw rows: N -> data/industry/cninfo_industry_change_raw.csv
membership rows: N -> data/industry/cninfo_sw1_membership.csv
```

这里 N 不预先假定，因为巨潮历史行业变更数量取决于实际数据。

然后运行 PIT 覆盖检查：

```powershell
python scripts/check_industry_coverage.py `
  --input data/industry/cninfo_sw1_membership.csv `
  --symbol 300308 `
  --backtest-start 2020-01-01T00:00:00+08:00
```

预期会明确报告 `PARTIAL_COVERAGE`，而不是把 2021-07-30 以前的行业向前填充。

## 单股验收标准

注意：巨潮接口返回的是“行业归属变动记录”，不是保证从研究起始日开始的完整每日/每日重建 membership。若某股票在查询区间内只有一条变更记录，这本身不代表历史数据错误，但意味着该股票在第一条记录之前没有可由本接口直接证明的 PIT 行业归属。

第一步先检查：

1. 能返回 `申银万国行业分类标准` 记录；
2. `行业门类` 非空；
3. 同一股票同一变更日期没有冲突的一级行业；
4. 区间按变更日期连续排列；
5. `available_time` 不早于 `effective_from`；
6. 本地 CSV 不提交 GitHub；
7. 若第一条记录晚于回测起始日，明确记录“历史覆盖起点”，回测只在有 PIT 行业归属的样本上计算，不能用当前行业向前填充。

只有“数据结构/区间正确”且“历史覆盖边界明确”后，才扩展 8 只股票。

## AKShare 原生申万历史成员路径

除巨潮变更接口外，AKShare 还提供 `stock_industry_clf_hist_sw`，其源码直接读取申万宏源研究的官方 `StockClassifyUse_stock.xls`，接口文档/源码将其定义为“个股行业分类变动历史”。它返回股票代码、计入日期、行业代码、更新日期，可直接用于重建历史行业归属。citeturn0search0turn2search1

本阶段优先使用这条 AKShare 原生路径，不要求 Tushare Token。

新增：

- `scripts/import_sw_industry_membership.py`
- `tests/test_import_sw_industry_membership.py`

归一化规则：

- `effective_from = start_date 00:00 +08:00`
- `effective_to = 下一次 start_date 00:00 +08:00`
- `available_time = start_date 次日 16:00 +08:00`
- 申万一级行业代码：取历史行业代码前两位并补为 `XX0000`
- 内部代码格式：`SW1:<六位一级行业代码>`

由于该历史接口返回的是行业代码而不是稳定的历史中文一级行业名称，本导入器暂不把当前名称表强行回填到历史记录；`industry_name` 暂使用规范化行业代码，避免分类版本错配。

示例：

`480301 -> SW1:480000`

因此，当前应先运行 AKShare 原生申万历史成员导入，重点检查：

1. `000333`
2. `000651`
3. `601318`
4. 原来的其余 5 只股票

如果这条路径能够给出 2020-01-01 以前或之后的完整历史起点，就以它作为 P13-M 的主数据集；巨潮接口作为交叉验证，而不是强制要求两个来源完全一致。
