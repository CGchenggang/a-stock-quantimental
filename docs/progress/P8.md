## Safety Rules

- Do not delete V1 scripts yet.
- Do not call cached or fallback observations "real-time" without provenance.
- Do not feed legacy single-index regime labels into the validated V2 model as if they were multi-input regimes.
- Do not use legacy proxy fund-flow labels as confirmed capital-flow facts.
- Do not migrate a legacy output until a V2 regression test exists.

## P8-C Regression Scope

Regression tests compare contract semantics rather than implementation details. Current coverage includes provenance/fallback, event_time versus available_time, daily and minute OHLCV preservation, missing timestamp rejection, and persisted cache timestamp preservation.

A V1/V2 mismatch is allowed only when the V2 contract intentionally changes behavior; such a change must be explicit and tested.

## P8-D Regression Scope

A legacy snapshot is not realtime-admissible unless an explicit availability timestamp is supplied, and even then the adapter keeps it marked as compatibility input until field-level PIT semantics are migrated.

## P8-F Provider Adapter Scope

Added focused adapters for the highest-value legacy market payloads: realtime quote, daily history, and intraday K-line results. Each adapter requires an explicit V2 `available_time`; intraday data additionally requires an explicit `scale` and `klines` list so an unknown-granularity payload cannot enter the V2 intraday contract.

These adapters preserve the original payload rather than recomputing values, and preserve fallback/provenance metadata through `ProviderResult`. They are compatibility adapters, not claims that the underlying V1 source is PIT-complete.

## P8-F Provider Equivalence Fixtures

Added fixed V1-shaped fixtures covering realtime quote, daily history, daily fallback, and intraday K-line payloads. The tests assert that the V2 provider adapters:

- retain the original payload object and its V1-computed fields;
- do not recompute price, percentage, moving-average, volume-ratio, or trend fields;
- preserve fallback/source/warning semantics;
- preserve intraday scale, row count, and OHLCV rows;
- require explicit V2 availability time independently of the V1 fetch timestamp.

This establishes behavioral equivalence at the provider boundary without treating the fixtures as live market data or proving that the legacy sources themselves are PIT-safe.


## P8-G Provider Call Boundary

Added `LegacyMarketProvider` as the first executable V2 provider boundary for selected V1 quote and daily-history functions. The adapter receives V1 fetchers by dependency injection, wraps their unchanged payloads as `ProviderResult`, and requires explicit V2 availability metadata. Regression tests verify payload identity, provenance type, and preservation of the requested daily window.

The boundary deliberately does not import or execute V1 scripts implicitly. This keeps the migration reversible and allows the next step to replace the injected fetchers with native V2 providers without changing downstream consumers.


## P8-H Quote Scope Alignment

Aligned the V1 full-market realtime snapshot with the V2 `quote(symbols)` contract. The legacy-backed provider now returns only requested normalized symbols while retaining the complete V1 payload under `legacy_payload` for provenance/audit. This prevents a silent universe expansion in downstream V2 consumers and preserves the original source evidence.


## P8-I Historical End-Date Guard

Added a migration guard for the legacy daily-history provider. V1 `get_stock_hist()` can append today's realtime quote when its historical endpoint is behind; the V2 legacy provider now rejects a payload whose `latest_date` exceeds the requested `end` date. This prevents that V1 convenience behavior from silently crossing a historical backtest boundary.

This is an end-date guard, not a claim that the legacy provider is fully PIT-safe. Historical backtests still require an availability-aware PIT source/store; the compatibility provider is intended for migration and current-data workflows.


## P8-J Intraday Provider Boundary

Extended the V2 `MarketProvider` contract with an optional intraday operation and bridged the legacy minute-K-line function through `LegacyMarketProvider`. The adapter preserves `scale`, `datalen`, OHLCV rows, source provenance, and explicit availability time. Supported scales are constrained to the legacy source's 1/5/15/30/60-minute semantics, with regression tests for invalid parameters and payload preservation.


## P8-K Provider-to-Research Integration

Connected the legacy-backed MarketProvider to the V2 research path rather than leaving the migration at adapter tests:

- legacy_runtime.build_legacy_market_provider() is the compatibility factory; V2 core code does not import V1 functions directly.
- build_research_packet_from_provider() consumes quote and daily ProviderResult objects and builds an evidence-only ResearchPacket.
- The research packet records provider availability/provenance and a structured data-health summary including missing ratio, fallback ratio, warnings, and realtime admissibility.
- ResearchOrchestrator.build_from_provider() exposes the provider-backed packet construction to the existing agent orchestration boundary.
- No factors, model probabilities, expected returns, or risk conclusions are inferred by this integration. Those remain downstream quantitative stages.
- Legacy intraday payloads without a V1 timestamp use the adapter boundary completion time only as fetched_at; this is explicitly not treated as the market event time.


## P8-L Provider-backed Research CLI

Added the first end-to-end V2 research entry point. The `research` CLI command builds a legacy-backed MarketProvider through the compatibility factory, consumes quote and daily results, and serializes an evidence-only ResearchPacket. The command deliberately does not run factors, probability models, expected-return estimation, or risk scoring; those remain downstream stages. A regression test verifies that the CLI crosses the provider boundary and preserves the no-model-yet state.


## P8-M Market-Regime Input Bridge

Extended the V2 MarketProvider boundary with optional index and sector-board operations and bridged the corresponding V1 functions. Added `LegacyMarketInputs` to derive explicitly labeled market-regime inputs from the V1 full-market quote snapshot, index daily data, and sector board data.

The adapter currently provides proxy inputs for breadth, limit-up/down pressure, index trend, and sector dispersion. It deliberately leaves `turnover_z`, `volatility_z`, and `liquidity` missing because the current V1 functions do not provide a PIT-complete standardized history for those measures. Missing fields are surfaced explicitly rather than filled with fabricated values. This allows the existing P3 classifier to remain conservative and return lower confidence or UNKNOWN when evidence is insufficient.


## P8-N ResearchPacket Regime Integration

Connected LegacyMarketInputs to the provider-backed research path. ResearchPacket.market now carries P3-compatible regime_inputs, the resulting regime and confidence from the existing classifier, index/quote/sector provenance, explicitly labeled proxy fields, and explicitly missing regime inputs.

The integration remains conservative: no missing turnover, volatility, or liquidity value is synthesized. Consequently, the current legacy-backed research path can produce UNKNOWN market regime with zero confidence when evidence is incomplete. This is intentional until a PIT-complete source for those inputs is migrated.


## P8-O Regime Activity and Volatility Inputs

Added two further regime inputs:

- Index volatility: the legacy index daily adapter now computes 20-session return volatility and a rolling historical volatility z-score when sufficient history exists.
- Market turnover: the V1 full-market quote snapshot is aggregated into a dated local observation series. A turnover z-score is exposed only when enough dated observations exist; the current local series is explicitly marked `pit_ready=false` and is therefore not admitted into the P3 PIT regime input yet.

This deliberately separates a usable runtime observation from a backtest-ready historical feed. No single current turnover observation is converted into a fake historical z-score. Volatility is likewise derived only from the dated index daily history returned by the provider.


## P8-P PIT Admissibility Gate

Added an explicit decision-time gate to the provider-backed research path.

- A ProviderResult is PIT-admissible only when available_time exists and available_time <= decision_time; equality is intentionally admissible.
- Future-dated quote, index, and sector results are excluded from regime inputs rather than merely lowering a health score.
- Future quote data is excluded from the ResearchPacket market facts, and future daily data is excluded from stock facts.
- data_quality now reports decision_time, pit_admissible_ratio, future_data_count, and an overall pit_admissible flag.
- The existing availability_complete field remains separate from PIT admissibility: having a timestamp does not make future data legally usable.
- Regression tests cover future timestamps and the exact decision-time boundary.

This is the first explicit look-ahead guard at the provider-to-research boundary. It does not make the legacy source historically PIT-complete; it only prevents known future-available observations from crossing the V2 decision boundary.


## P8-Q Central PIT Gate and Liquidity Provenance

- Centralized ProviderResult PIT admissibility in the provider contract layer.
- The shared gate requires a non-fallback result with an explicit available_time that is no later than decision_time.
- ResearchPacket construction and legacy market-regime input bridging now use the same PIT rule instead of maintaining independent timestamp comparisons.
- Added explicit provenance for the remaining liquidity gap: the current legacy source does not provide a dedicated PIT-complete liquidity history, so the liquidity input remains None.
- Added regression coverage for the shared PIT behavior and the explicit liquidity-missing reason.


## P8-R Structured Provider PIT Status

Replaced the provider-layer PIT boolean's internal decision logic with a reusable `PitStatus` classification:

- `ADMISSIBLE`: `available_time <= decision_time` and the result is not fallback.
- `FUTURE`: the result becomes available after the decision boundary.
- `MISSING_TIME`: no `available_time` is supplied.
- `FALLBACK`: the provider explicitly marks the result as fallback.
- `INVALID_TIME`: the available or decision timestamp cannot be normalized.

`pit_admissible()` remains as the compatibility boolean API, but now delegates to `pit_status()`. Research health reporting additionally exposes `pit_status_counts`, while `future_data_count` is now specifically the count of `FUTURE` observations rather than every non-admissible observation. This keeps future-data leakage, missing provenance, fallback data, and malformed timestamps distinguishable for the later P0/P1 data-quality layer.


## P8-S Shared Data Quality PIT Summary

Added `astock_v2.data_quality.summarize_pit()` as the shared data-quality boundary for provider results. It consumes the provider-layer `PitStatus` classification and returns a structured summary without modifying source observations. Research health now uses this shared summary, so PIT ratios and reason-specific status counts have one implementation path. This prepares P1/P2/P3 consumers to reuse the same admissibility semantics instead of rebuilding timestamp logic locally.


## P8-T Regime Data-Quality Integration

The P3 regime-input bridge now reuses the shared `summarize_pit()` data-quality boundary. `LegacyMarketInputs.regime_inputs(decision_time=...)` returns `data_quality` covering the index, market-wide quote, sector, and turnover provider results. The research packet exposes this as `regime_data_quality`, so regime evidence carries the same PIT status vocabulary as the broader Research health layer. No regime input value is fabricated or silently promoted when its provider result is not PIT-admissible.


## P8-U Factor Input PIT Gate

The repository does not yet contain an independent P2 factor-calculation module, so P8-U establishes the input boundary without inventing factor logic.

Added `astock_v2.factor_inputs.gate_factor_inputs()`:

- accepts provider results plus an explicit decision time;
- admits only `PitStatus.ADMISSIBLE` observations;
- retains rejected observations for diagnostics instead of dropping them silently;
- exposes the shared `DataQualitySummary` so factor consumers use the same PIT vocabulary as Research and Regime;
- treats exact decision-time availability as admissible;
- never repairs, substitutes, or fabricates rejected observations.

This creates the intended P2 entry contract:

`ProviderResult -> PitStatus -> DataQualitySummary -> Factor Input Gate -> Factor Calculation`

The gate is deliberately calculation-agnostic. It will be consumed by the actual P2 factor implementation when that module is introduced.



## P8-V P2 Factor Contract

Added `astock_v2.factor_contracts.FactorOutput` as the quantitative output contract. A factor output carries its name, symbol, decision time, value, shared PIT data quality, provenance, and optional metadata. A factor is not admissible downstream unless it has a value and all provider inputs are PIT-admissible.

## P8-W Probability Input Gate

Added `astock_v2.probability_inputs.gate_probability_inputs()` as the boundary immediately before probability-model execution. It admits only admissible factor outputs and can require named factors. Missing required factors, future-data-derived factors, fallback-derived factors, malformed-timestamp inputs, and missing factor values therefore block model execution rather than being silently substituted.

The resulting quantitative path is now:

`ProviderResult -> PIT Gate -> FactorOutput -> Probability Input Gate -> Probability Model`

No probability value is generated by this compatibility work.
