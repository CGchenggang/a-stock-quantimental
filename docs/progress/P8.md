## Safety Rules

- Do not delete V1 scripts yet.
- Do not call cached or fallback observations "real-time" without provenance.
- Do not feed legacy single-index regime labels into the validated V2 model as if they were multi-input regimes.
- Do not use legacy proxy fund-flow labels as confirmed capital-flow facts.
- Do not migrate a legacy output until a V2 regression test exists.

## P8-C Regression Scope

Regression tests compare contract semantics rather than implementation details. Current coverage includes provenance/fallback, event_time versus available_time, daily and minute OHLCV preservation, missing timestamp rejection, and persisted cache timestamp preservation.

A V1/V2 mismatch is allowed only when the V2 contract intentionally changes behavior; such a change must be explicit and tested.

## P8-D Regression Scope

The V2 orchestration adapter accepts legacy collector outputs without executing legacy scripts inside the V2 layer. A legacy snapshot is not realtime-admissible unless an explicit availability timestamp is supplied, and even then the adapter keeps it marked as compatibility input until field-level PIT semantics are migrated.

## P8-D CLI Integration

Added a V2 `legacy-snapshot` CLI command that normalizes existing V1 morning/pre-market JSON through the orchestration boundary. It does not execute V1 collectors and does not infer realtime status from `generated_at`.
