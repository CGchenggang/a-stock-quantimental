## Implemented

- P7.1 decision snapshot: immutable model/factor/data-quality context is persisted in a JSONL ledger.
- P7.2 outcome backfill: T+1/T+3/T+5/T+10 returns can be added without replacing the original snapshot.
- P7.2 review scheduling: due review horizons are detected from decision time.
- P7.3 prediction versus reality: Brier score and return-error metrics are available.
- P7.4 postmortem schema: structured causes and data-quality flags are stored separately from the historical prediction.
- P7.5 cumulative outcome metrics: aggregate realized/expected returns and errors, including regime breakdown.
- P7.5 model feedback: evaluation output can be consumed by later calibration/model-version workflows; this phase does not rewrite model parameters automatically.
- CI: GitHub Actions workflow runs the test suite on main pushes and pull requests.

## Design Constraints

- Historical decision snapshots are not overwritten by postmortem conclusions.
- Quantitative outputs remain the source of truth; the Agent records evidence and explanations.
- A single realized outcome does not automatically change model weights.
- Outcome data must be based on observations available after the decision time.
