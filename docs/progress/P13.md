# P13 — 本地历史数据与多市场研究架构

## 目标

把历史行情、海外市场、国内宏观与政策/事件纳入统一的数据契约，同时保持严格的 point-in-time（PIT）约束。

## P13-A：本地历史数据目录

新增 `astock_v2.data.catalog`：

- `HistoricalRecord`：统一记录 symbol、event_time、available_time、source、source_type、value、revision、raw_ref、quality。
- `DatasetSpec`：声明数据集的资产范围、频率、主数据源、本地路径和 PIT 要求。
- `DEFAULT_DATASETS`：预留 A 股、A 股指数、海外指数、汇率、大宗商品、利率和政策事件数据集。

原则：**原始数据可复现、清洗数据可重建、PIT 数据可审计**。历史行情缺少真实的 available_time 时，不能用 fetch time 伪造。

## P13-B：跨市场上下文

新增 `MarketContext`，统一承载：

1. A 股市场数据；
2. 海外市场数据；
3. 宏观数据；
4. 政策/事件数据。

所有记录在进入研究模型前，都必须通过 `available_time <= decision_time`。

## P13-C：政策/事件

新增中性的 `PolicyEvent` 契约。

政策、监管、产业政策、贸易政策、地缘事件等首先作为**可追溯事件**进入系统，而不是主观政治评分。AI Agent 可以负责发现、整理和解释事件，但不得直接修改量化概率、因子值或给事件赋予未经验证的收益方向。

## P13-E：本地历史数据落盘管线（工程完成）

新增 astock_v2.data.local_store.LocalHistoricalStore 与 scripts/download_cn_stock_history.py：

- 原始供应商响应按 snapshot 保存，并记录 SHA-256 摘要；
- 清洗后的 HistoricalRecord 按数据集/股票拆分为 JSONL；
- 同一 (event_time, revision) 幂等覆盖，避免重复下载造成重复行；
- 文件写入采用临时文件 + 原子替换，避免半写文件污染研究数据；
- 所有本地历史记录必须具有显式、带时区的 event_time 与 available_time；
- 当前 A 股日线下载器使用 AKShare stock_zh_a_hist，并把“收盘后可用”建模为明确的 16:00（Asia/Shanghai）可用时间假设，而不是把抓取时间冒充历史可用时间。AKShare 文档说明该接口为沪深京 A 股日频数据，并提示当日收盘价应在收盘后获取。
- 不复权、前复权、后复权作为不同数据版本保留，后续回测不得混用。

**P13-E 的工程部分已完成。** 实际历史数据文件不直接提交到 GitHub：需要在用户本地运行下载器，以保证数据源、网络环境和落盘数据可追溯。

## P13-D：后续实现

下一步不是一次性下载全部数据，而是建设可增量更新的数据落盘管线：

```
Provider
  ↓
Raw snapshot
  ↓
Normalize / validate
  ↓
HistoricalRecord
  ↓
PIT gate
  ↓
Factors / Regime / Probability / OOS
```

优先顺序：

1. A 股日线历史行情；
2. A 股指数/行业历史行情；
3. 海外指数、汇率、利率、主要商品；
4. 国内宏观数据；
5. 政策/公告事件；
6. 将这些输入接入 Market Regime 与 OOS 验证。

## 明确不做

- 不把新闻情绪直接等同于市场方向；
- 不把“政治因素”做成主观打分；
- 不把海外市场数据按错误时区加入回测；
- 不使用未来修订后的财务数据预测过去；
- 不把 fetch time 当作历史信息的 available_time；
- AI Agent 不得修改 Quant 层的数值输出。

## P13-F：真实本地数据 → 因子 → Walk-forward/OOS（工程完成，待本地实跑验收）

新增：

- `astock_v2.data.historical_loader.load_daily_provider_result`：从本地 JSONL 恢复 PIT 可用日线，并按 event_time/revision 选择在 decision_time 已经可见的最高 revision；未来、缺失 available_time 的记录不会进入因子层。
- `astock_v2.local_pipeline.build_local_factor_rows`：以固定的 16:00（Asia/Shanghai）日线决策边界生成 momentum、volatility、trend、volume_ratio 四类因子；标签定义为下一交易日收盘收益是否为正。
- `scripts/run_local_300308_oos.py`：读取用户本地 300308 数据，运行 252 日训练 / 20 日测试 / 20 日滚动步长的 walk-forward 概率评估，只输出 OOS Accuracy、Brier 和校准信息，不直接生成交易建议。
- 新增 PIT revision 边界测试，防止“未来 revision 覆盖当时已知 revision”。

### 交易日历与非交易日约束

本地日线管线**不按自然日生成交易记录**。`event_time` 来自实际历史行情中的已有交易日，因此周六、周日以及法定节假日没有行情记录时，不会被构造成虚假的交易日；“下一交易日”也是 `event_times` 中的下一条实际行情记录。walk-forward 的 `gap=1` 同样按样本/交易日记录隔离，而不是按自然日加一天。

需要注意：当前数据管线依赖数据源提供的实际交易日集合，并没有把某个固定国家/地区交易所日历硬编码进因子计算层；未来接入多市场时，应为每个交易所/资产建立独立交易日历和时区规则。

### 本地实跑验收

2026-09-27 用户本地已成功下载 300308 日线历史 **1633 条**，首次无 embargo 的真实 OOS 运行得到 1612 个因子样本、68 个 walk-forward 窗口、1360 个 OOS 预测，Accuracy=0.5169、Brier=0.2505。该结果**不作为最终验收指标**，因为检查发现训练集最后一个样本的下一交易日标签可能与测试集第一天重叠。

因此 P13-F 已增加通用 `gap`/label embargo 机制，并要求本地 OOS 脚本使用 **1 个交易日 gap**，避免训练标签使用测试期尚未可知的收盘结果。下一次本地运行才作为严格 PIT/OOS 指标验收依据。

GitHub 仓库不保存用户本地历史数据。


### 严格 PIT/OOS 验收结果（2026-09-27）

用户本地在最新代码上完成严格 OOS 实跑：

- 本地因子样本：1612
- walk-forward 窗口：67
- 训练/测试：252 / 20
- 滚动步长：20
- label embargo：1 个交易日
- OOS 预测数：1340
- 基准：constant_0.50、train_rate
- 模型：四个单因子 Logistic + 四因子 Logistic

关键结果：

| 模型 | Accuracy | Brier | Log Loss |
|---|---:|---:|---:|
| constant_0.50 | 0.505970 | 0.250000 | 0.693147 |
| train_rate | 0.507463 | 0.250493 | 0.694137 |
| volume_ratio | 0.519403 | 0.250209 | 0.693630 |
| 四因子 Logistic | 0.521642 | 0.250269 | 0.693764 |

严格 OOS 下，四因子模型相对 constant_0.50 的 Accuracy 提升约 1.57 个百分点，但 Brier 和 Log Loss 均略差于常数 0.50 基准。因此当前结果只能说明存在轻微的分类准确率提升，尚不能证明概率预测质量或稳定可交易优势。

四因子校准样本主要集中在 p≈0.47–0.53；高概率区间样本很少，当前不适合据此设置交易阈值或直接进入实盘决策。

**P13-F 阶段结论：**
1. 本地历史数据 → PIT → 因子 → 1 日 label embargo → walk-forward/OOS 的工程链路已完成并通过本地测试。
2. 当前概率模型不通过“概率质量/交易优势已验证”的模型验收。
3. 后续优先进入因子诊断与特征改进：先检查因子分布、标准化/尺度、单因子边际信息、时间稳定性，再考虑引入 Market Regime；不应因为 52.16% Accuracy 就直接扩大模型复杂度。


### P13-G：因子诊断（下一步）

新增 `scripts/diagnose_local_300308_factors.py`，在不训练新模型的前提下检查：

- 四因子的均值、中位数、标准差、5%/95%分位数与极值；
- 因子与下一交易日涨跌标签的样本相关性（仅作描述性诊断）；
- 五分位因子桶的正收益率，观察是否存在单调关系。

该脚本的结果用于决定下一轮因子定义/标准化方案，不作为 OOS 验收指标。实际运行仍使用用户本地历史数据，GitHub 不保存行情文件。


### P13-G 诊断结论与下一轮实验

本地 300308 因子诊断显示：

- 标签正例率约 50.31%，类别本身基本平衡。
- momentum 与 trend 的五分位结果呈明显的非单调形态：最低分位上涨率较高，中间分位较低，最高分位又回升；简单线性 Logistic 难以表达这种形态。
- volatility 与 volume_ratio 的线性相关性较弱，分桶上涨率也未表现出稳定单调关系。
- 当前四因子量纲不同，volume_ratio 存在明显更大的极值范围；因此需要区分“因子本身没有信息”和“尺度/极值影响优化”的问题。

因此 P13-G 下一轮不直接引入 Market Regime，而先进行严格 OOS 的因子表示实验。新增 scripts/run_local_300308_factor_variants_oos.py，比较：

1. raw 四因子；
2. raw + momentum² + trend²；
3. 每个 walk-forward 训练窗口内 winsorize + z-score；
4. 训练窗口内标准化后再加入 momentum² + trend²。

所有标准化参数只从对应训练窗口拟合，测试窗口完全隔离，继续使用 1 个交易日 label embargo。该实验用于判断当前瓶颈是线性表示、尺度/极值，还是因子本身缺乏稳定信息。


### P13-G 严格 OOS 因子表示实验结果（2026-09-27）

用户本地完成四种因子表示方式的严格 walk-forward/OOS 对比：

| 表示方式 | Accuracy | Brier | Log Loss |
|---|---:|---:|---:|
| raw 四因子 | 0.521642 | 0.250269 | 0.693764 |
| quadratic | 0.520149 | 0.250332 | 0.693893 |
| standardized | 0.517164 | 0.253510 | 0.700743 |
| standardized_quadratic | 0.520149 | 0.254102 | 0.702348 |
| constant_0.50 基准 | 0.505970 | 0.250000 | 0.693147 |

其中 quadratic 为 raw 四因子增加 momentum²、trend²；standardized 在每个训练窗口内单独拟合 winsorize + z-score；standardized_quadratic 则在训练窗口内标准化后再加入平方项。所有变换均未使用对应测试窗口的数据，继续使用 1 个交易日 label embargo。

结果表明：

1. raw 四因子仍是四种方案中整体表现最好的表示方式；增加平方项没有改善 OOS 指标。
2. 标准化不仅没有改善，Brier 和 Log Loss 均明显恶化，说明当前问题不能简单归因于因子量纲或极值导致的优化不稳定。
3. 四因子模型相对于 constant_0.50 的 Accuracy 提升仍约 1.57 个百分点，但 Brier=0.250269、Log Loss=0.693764 均略差于无信息基准，因此仍不能视为概率质量已经得到验证。
4. quadratic 与 standardized 方案的变化幅度较小，不能据此选择“更复杂”的表示方式；当前应避免根据单次 OOS 的 Accuracy 进行模型挑选。

**P13-G 阶段结论：** 当前证据不支持“只要换一种线性表示/标准化方式就能解决问题”的假设。研究重点应从表示层转向**因子定义与信息源本身**。

下一阶段建议按以下顺序推进：

1. 重新设计少量具有明确经济含义的因子，并保持单因子可解释、可 PIT 验证；
2. 增加不同预测 horizon 的标签实验，区分短期方向信号与更长周期信号是否被当前“下一交易日涨跌”标签掩盖；
3. 将相同因子管线扩展到多个具有不同规模/行业/波动特征的 A 股样本，检查信号是否具有横截面稳定性；
4. 只有在因子在多个样本和 OOS 时间段表现出稳定信息后，再把 Market Regime 作为条件变量接入；
5. 对任何看起来有效的候选方案，增加时间分段稳定性与置信区间/重采样检验，避免把单一 OOS 窗口中的偶然差异当成真实优势。

因此，**P13-G 不接受任何新的因子表示方案作为生产模型**；raw 四因子仅作为当前基线保留。


### P13-H：标签预测 horizon 实验设计

P13-G 表示层实验未改善 OOS 概率质量，因此下一步不继续增加模型复杂度，而测试当前标签定义是否与因子信息周期匹配。

新增 `scripts/run_local_300308_label_horizon_oos.py`，在同一套四因子基础上比较：

- 1 个交易日方向标签；
- 5 个交易日方向标签；
- 10 个交易日方向标签。

每个 horizon 的 walk-forward gap 分别设置为对应 horizon，确保训练样本的未来标签不会进入测试期。该实验只改变预测目标，不改变因子输入和模型形式，因此可以区分“因子没有信息”和“下一交易日标签过短/噪声较大”这两种可能性。

验收仍以 OOS Accuracy、Brier、Log Loss 为主，并以对应 horizon 的训练集正例率基准进行比较。任何单一 horizon 的偶然改善都不直接进入生产模型。
