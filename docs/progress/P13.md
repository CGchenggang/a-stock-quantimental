# P13 — 本地历史数据与多市场研究架构

## 目标

把历史行情、海外市场、国内宏观与政策/事件纳入统一的数据契约，同时保持严格的 point-in-time（PIT）约束。

## P13-A：本地历史数据目录

新增 `astock_v2.data.catalog`：

- `HistoricalRecord`：统一记录 symbol、event_time、available_time、source、source_type、value、revision、raw_ref、quality。
- `DatasetSpec`：声明数据集的资产范围、频率、主数据源、本地路径和 PIT 要求。
- `DEFAULT_DATASETS`：预留 A 股、A 股指数、海外指数、汇率、大宗商品、利率和政策事件数据集。

原则：**原始数据可复现、清洗数据可重建、PIT 数据可审计**。历史行情缺少真实的 available_time 时，不能用 fetch time 伪造。

## P13-B：跨市场上下文

新增 `MarketContext`，统一承载：

1. A 股市场数据；
2. 海外市场数据；
3. 宏观数据；
4. 政策/事件数据。

所有记录在进入研究模型前，都必须通过 `available_time <= decision_time`。

## P13-C：政策/事件

新增中性的 `PolicyEvent` 契约。

政策、监管、产业政策、贸易政策、地缘事件等首先作为**可追溯事件**进入系统，而不是主观政治评分。AI Agent 可以负责发现、整理和解释事件，但不得直接修改量化概率、因子值或给事件赋予未经验证的收益方向。

## P13-D：后续实现

下一步不是一次性下载全部数据，而是建设可增量更新的数据落盘管线：

```
Provider
  ↓
Raw snapshot
  ↓
Normalize / validate
  ↓
HistoricalRecord
  ↓
PIT gate
  ↓
Factors / Regime / Probability / OOS
```

优先顺序：

1. A 股日线历史行情；
2. A 股指数/行业历史行情；
3. 海外指数、汇率、利率、主要商品；
4. 国内宏观数据；
5. 政策/公告事件；
6. 将这些输入接入 Market Regime 与 OOS 验证。

## 明确不做

- 不把新闻情绪直接等同于市场方向；
- 不把“政治因素”做成主观打分；
- 不把海外市场数据按错误时区加入回测；
- 不使用未来修订后的财务数据预测过去；
- 不把 fetch time 当作历史信息的 available_time；
- AI Agent 不得修改 Quant 层的数值输出。
